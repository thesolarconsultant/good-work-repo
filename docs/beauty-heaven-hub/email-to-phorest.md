# Request to Phorest for API access (Jess sends this)

**How Phorest says to ask** (from its developer docs, read in this session): use the Support request form at
https://support.phorest.com/hc/en-us/requests/new?ticket_form_id=360000928660 and **include the Phorest account number**. The request
**must come from an email address that is associated with the business in Phorest**, so Jess or the account's administrator sends it.
For questions about using the API, Phorest lists api-requests@phorest.com. Fill the brackets before sending.

---

**Subject:** API access request: Beauty Heaven Hub, account [ACCOUNT NUMBER]

Hi Phorest Support,

I'm [NAME], [owner / manager] at Beauty Heaven Hub, Phorest account number **[ACCOUNT NUMBER]** (online booking page
phorest.com/salon/beautyheaven1). I'm writing from the email address registered to our account.

We would like to request **Third Party API access**. We have appointed a developer partner, **Good Work** ([CONTACT NAME, EMAIL]), to
connect our new website and our phone and messaging assistants to our diary, and we authorise them to use the API on our behalf.

What we need it for: reading our services, staff and availability; looking up clients by phone number; and creating, rescheduling and
cancelling bookings, with booking notes. We will only use the data that is needed.

Could you please:
1. Issue API credentials for the **EU server**, ideally a dedicated API user for this integration.
2. Tell us whether API access is **included in our plan or has a cost**, and what it is.
3. Confirm whether a **test or sandbox** environment exists.
4. Tell us the recommended way to detect new, changed and cancelled bookings, as we understand webhooks are not supported.
5. Confirm whether the credentials can be **limited** to the functions above, so they do not expose staff payroll or personal details.
6. Share the current instructions for **embedding online booking** on our new website, including direct links by category, service and
   practitioner.
7. Let us know if there are any **terms or a data agreement** we need to sign for third-party access.

Thank you,
[NAME]
[JOB TITLE, BUSINESS NAME]
[PHONE NUMBER]

---

Notes for the user, not for the email:
- Phorest's docs say card payments and Phorest Pay are not available through the API, and webhooks are not supported (we poll).
- If Jess would rather email, she can send it to api-requests@phorest.com, but the support form is the route the docs give for getting access.
- When credentials arrive they go to Good Work through a password manager share or in a call, never by chat. Note the date received.
